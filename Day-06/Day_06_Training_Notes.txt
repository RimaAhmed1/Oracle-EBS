1. NORMAL PL/SQL PROCEDURE
============================================================

A normal database procedure can use:

DBMS_OUTPUT.PUT_LINE

to display output in SQL*Plus or another Oracle SQL tool.

Example:

CREATE OR REPLACE PROCEDURE RIMA_PR_TEST
IS
BEGIN
    DBMS_OUTPUT.PUT_LINE('WELCOME TO ORACLE DATABASE PROCEDURE!');
END;
/

To execute:

SET SERVEROUTPUT ON;

EXEC RIMA_PR_TEST;


============================================================
2. ORACLE EBS PROCEDURE
============================================================

A PL/SQL Stored Procedure registered as an Oracle EBS
Concurrent Program uses two mandatory OUT parameters:

ERRBUF  OUT VARCHAR2
RETCODE OUT NUMBER

ERRBUF:
Used for an error/status message.

RETCODE:
Used for the completion status of the concurrent request.

For EBS concurrent output, FND_FILE.PUT_LINE is used instead
of DBMS_OUTPUT.PUT_LINE.


============================================================
3. FND_FILE
============================================================

FND_FILE.PUT_LINE is used by an Oracle EBS concurrent
procedure to write information to the request output or log.

FND_FILE.OUTPUT
    -> Writes information to the Concurrent Request Output.

FND_FILE.LOG
    -> Writes information to the Concurrent Request Log.

Example:

FND_FILE.PUT_LINE(
    FND_FILE.OUTPUT,
    'WELCOME TO ORACLE EBS PROCEDURE!'
);


============================================================
4. REGISTERING A PL/SQL PROCEDURE IN ORACLE EBS
============================================================

After creating the procedure in the database, register it
in Oracle EBS.

STEP 1 - EXECUTABLE

Responsibility:
Application Developer

Navigation:
Concurrent -> Executable

Execution Method:
PL/SQL Stored Procedure

Execution File Name:
Name of the stored procedure.


STEP 2 - CONCURRENT PROGRAM

Navigation:
Concurrent -> Program

Create the Concurrent Program and attach the Executable.


STEP 3 - REQUEST GROUP

A Request Group is a collection of Programs and Reports.

Add the Concurrent Program to the required Request Group.


STEP 4 - RESPONSIBILITY

Attach the Request Group to the required Responsibility.


STEP 5 - USER

Assign the Responsibility to the required user.

7. SYSTEM-DEFINED EXCEPTIONS
============================================================

Examples covered:

NO_DATA_FOUND
TOO_MANY_ROWS
ZERO_DIVIDE

Example:

EXCEPTION
    WHEN NO_DATA_FOUND THEN
        DBMS_OUTPUT.PUT_LINE('INPUT A VALID EMPNO !!');

    WHEN OTHERS THEN
        DBMS_OUTPUT.PUT_LINE('CHECK YOUR PROGRAM !!!');


============================================================
8. USER-DEFINED EXCEPTION
============================================================

The steps discussed for a User-Defined Exception were:

1. DECLARE
2. CHECK
3. RAISE
4. HANDLE

General idea:

DECLARE
    MY_EXCEPTION EXCEPTION;

BEGIN

    -- CHECK condition

    IF condition THEN
        RAISE MY_EXCEPTION;
    END IF;

EXCEPTION

    WHEN MY_EXCEPTION THEN
        -- HANDLE exception

END;
/

============================================================
11. SYSDATE
============================================================

SYSDATE returns the current date from the Oracle Database.

Example:

SELECT SYSDATE
FROM DUAL;


============================================================
12. SYSDATE ORACLE EBS PROCEDURE
============================================================

Task:

Create a PL/SQL Stored Procedure to display the current date
when submitting the request in Oracle EBS.

The procedure:

1. Gets SYSDATE from DUAL.
2. Stores the date in a variable.
3. Writes information to the Concurrent Request Log.
4. Writes the current date to the Concurrent Request Output.
5. Is registered as a Concurrent Program.
6. Is submitted from an Oracle EBS Responsibility.

Example:

SELECT SYSDATE
INTO V_DT
FROM DUAL;

FND_FILE.PUT_LINE(
    FND_FILE.LOG,
    'YOU CAN SEE LOG DETAILS HERE!'
);

FND_FILE.PUT_LINE(
    FND_FILE.OUTPUT,
    'CURRENT DATE = ' || V_DT
);
